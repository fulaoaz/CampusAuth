# 验证记录与边界

本页汇总 2026 年 10 月 23 日对 0.3.0 开发产物进行的实际检查。它是源码项目的验证说明。GitHub 迁移后的发行包重新构建并核对文件与资源身份；每次发行的具体校验值及增量验证边界以 Release 随附的 `SHA256SUMS`、`VALIDATION.md` 为准。

原始日志、测试脚本、截图和构建产物保留在开发机，未纳入公开源码仓库。下列结果保留各自的运行环境与证据范围，不把界面模拟、协议模拟和目标硬件验证合并为一个结论。

## Windows 桌面

在已有 WebView2 `132.0.2957.127` 的 Windows x64 主机上完成：

- 标准版与完整离线版分别在隔离目录安装、启动和卸载，退出码均为 0，默认保留用户数据。
- 两个安装包内应用的哈希一致，版本与作者信息匹配；完整包解出的微软离线安装器签名有效、哈希匹配。
- 普通启动后的应用与全部 WebView 子进程没有 TCP 监听；原生托盘菜单退出后进程结束。
- 原生 IPC、账号接口与本机模拟认证网关交互通过；关闭窗口隐藏后，后台完成再次认证。
- 无系统标题栏、自定义窗口按钮、顶部双击、程序化拖动、浅深主题通过；文字大小调至 20、刷新保留和恢复默认 15 通过。
- 最终程序依赖表未发现 Python、Node.js、MSVC 可再发行 DLL 等额外运行时，保留 Windows 自带系统库依赖。

没有通过卸载系统运行时来测试缺失 WebView2 的机器。完整离线包的内嵌组件与安装分支已核对，但“干净系统缺少运行时”的完整安装流程尚未在虚拟机实测。CampusAuth 程序和安装包没有代码签名；有效微软签名属于内嵌的微软安装组件。

## Linux 桌面

完整 AppImage 在 Ubuntu 22.04 和 Ubuntu 24.04 容器用户空间中，使用非 root 用户实际启动并渲染 1240×850 中文应用窗口：

- 目标系统没有安装 GTK3 / WebKitGTK 软件包。
- 没有 `/dev/fuse`，使用 `APPIMAGE_EXTRACT_AND_RUN=1`。
- 应用、WebKit 网络进程和网页进程实际存在；欢迎向导与界面截图检查通过。
- 没有禁用 WebKit 沙箱，也没有使用特权容器。

两种用户空间使用相同的 WSL Linux 内核，显示为 Xvfb / X11 和软件渲染；没有代表所有发行版、物理 GPU 或原生 Wayland。修复后的 AppImage 补入此前遗漏的文字渲染库，修复前的缺库产物不计为通过。

标准 DEB 在已有发行版 GTK / WebKitGTK 的 Ubuntu 22.04 环境完成安装、辅助程序检查、电源预览和卸载；这不代表缺依赖且离线的 DEB 安装已经通过。

## 服务器与协议

| 检查 | 数量 | 实际范围 |
|---|---:|---|
| x64 最终程序 API / 会话 | 45 项 | 最终静态二进制、真实本地 HTTP 请求 |
| 组件部署模式与维护 | 26 项 | 最终静态二进制、隔离部署目录、四种组件模式 |
| 局域网与代理约束 | 9 项 | 同版本服务器代码的前序功能产物、本地网络请求 |
| root 管理后的文件归属 | 6 项 | root 写入、低权限用户读取与认证 |
| systemd 运行 | 17 项 | 实际 PID 1 systemd 环境 |
| 自动恢复 | 6 项 | 注入服务启动失败后的恢复行为 |
| ARM64 程序 | 40 项 | QEMU 下实际执行静态 ELF、CLI、HTTP 与本机协议模拟 |

这些检查没有统一汇总成“最终程序全部测试数”：部分广覆盖检查执行于同版功能代码的前序产物，最终程序另行核对身份，并重跑 API / 会话和部署模式检查。ARM64 使用 QEMU，不代表物理 ARM64 设备验证。

校园网认证均使用本机可丢弃的 ePortal 模拟网关，包括实际 HTTP 编码、Cookie、登录、注销、账号轮换和在线连接保护；没有使用真实校园账号证明目标校园网连通。

## 界面交互

共享 React 界面完成 28 项功能检查和 11 项文字大小专项检查，覆盖账号增删改、密码留空保留、停用与顺序、重连设置、向导、诊断预览、浅深主题与手机布局。

文字专项检查覆盖默认 15、预设、滑杆 20、偏好持久化、恢复默认，以及最大字号下桌面和手机向导按钮可见。这些界面检查使用隔离数据；原生桌面集成另有前述 Windows / Linux 运行检查。

## 尚未覆盖

- 真实学校网关、不同校园网定制与实际账号登录。
- 真实睡眠、休眠、关机、RTC 唤醒和完全关机开机。
- Windows 干净环境缺少 WebView2 的端到端离线安装。
- 物理 ARM64 设备、原生 Wayland 和不同 GPU / 驱动组合。
- 公网 HTTPS 反向代理的实际证书和公网部署。
- 后续新版本的完整更新与升级链路；当前仅发布本版本，不把查询当前 Release 视为跨版本升级验证。
